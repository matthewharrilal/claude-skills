# PERCEPTUAL DEEPENING PROTOCOL
## A Forcing Function for Soul Extraction Through Iterative Visual Discovery

═══════════════════════════════════════════════════════════════════════════════

**PURPOSE:** This protocol forces iterative visual discovery to extract the
ineffable qualities ("soul") that make a design feel like itself and not like
a generic approximation.

**CORE PRINCIPLE:** Insights emerge from repeated failure and perceptual
deepening, NOT from pre-defined checklists. You don't know what you're looking
for until you find it.

**ANTI-PRINCIPLE:** Surface-level analysis, analytical checklists, assuming you
know what to look for, stopping when something "seems right."

═══════════════════════════════════════════════════════════════════════════════

---

# PART 1: THE PHILOSOPHY

## Why Checklists Fail

A checklist says: "Check for ball terminals."

But ball terminals weren't discovered by someone who knew to look for them. They
were discovered by someone who:

1. Built something that looked wrong
2. Asked "what's wrong?"
3. Got a surface answer that didn't fix it
4. Asked "what ELSE is wrong?"
5. Kept looking
6. Noticed something about the letter endings
7. Zoomed in
8. Realized: "These have round balls, mine have tapered ends"

The insight emerged from **looking harder at failure**, not from knowing what to check.

## The Perceptual Discovery Process

```
LOOK → It's wrong → WHY? → Surface answer → Still wrong →
LOOK HARDER → What haven't I noticed? → Go deeper →
What's the ONE thing? → Keep looking → Eventually: "Oh, THAT"
```

This process cannot be shortcut. Each iteration reveals something the previous
iteration couldn't see.

## Analytical vs. Perceptual Questions

| ANALYTICAL (Wrong Approach) | PERCEPTUAL (Right Approach) |
|-----------------------------|----------------------------|
| "What are the CSS properties?" | "What am I seeing that I can't articulate yet?" |
| "What's the border width?" | "If I trace this edge with my finger, where does it feel different?" |
| "Is it italic?" | "What's the quality of this curve that makes it feel THIS way?" |
| "Check for ball terminals" | "Something about these letter endings is different. What is it?" |
| "Does it have a container?" | "Why does theirs feel like floating and mine feels trapped?" |
| "What color is it?" | "What's the quality of this color that makes it punch vs feel muted?" |
| "Is the spacing correct?" | "Where does the space feel generous vs cramped vs awkward?" |

**Analytical questions assume you know what to look for.**
**Perceptual questions force you to keep looking until something emerges.**

## The Forcing Questions

At each stage, these questions force deeper looking:

### Stage 2 - Squint Test:
- "If I blur my eyes, what's the dominant shape I see?"
- "What's the overall visual weight? Heavy? Light? Balanced? Unbalanced?"
- "What's the feeling? Trapped? Floating? Cramped? Spacious?"
- "If I had to describe the vibe in one word, what is it?"

### Stage 3 - Point:
- "Gun to my head, what's the ONE thing that's most wrong?"
- "What would an expert notice first?"
- "What am I avoiding looking at?"

### Stage 4 - Zoom:
- "What do I see at this scale that I couldn't see before?"
- "What's happening at the edges?"
- "What's happening where elements meet?"
- "What ELSE? (ask this 3 times minimum)"

### Stage 5 - Name:
- "Even if I'm wrong, what would I call this?"
- "How would I describe this to someone who can't see it?"
- "What verb describes what's happening here? (floating, trapped, pressing, lifting...)"

### Stage 8 - Re-compare:
- "Is this closer or did I make it worse?"
- "What's STILL wrong?"
- "What new problem did this fix create?"

### Stage 9 - Deepen:
- "What haven't I looked at yet?"
- "What's the thing I've been assuming is fine?"
- "Where am I afraid to look?"

# PART 3: SUB-AGENT ARCHITECTURE FOR ITERATIVE AUDITING

## Overview

The perceptual deepening loop requires multiple iterations with visual comparison.
This requires sub-agents that can:
1. Take screenshots
2. Compare visually
3. Report perceptual observations (not analytical measurements)
4. Make targeted changes
5. Re-compare
6. Continue until convergence

## Sub-Agent Structure

```
═══════════════════════════════════════════════════════════════════════════════
SUB-AGENT HIERARCHY
═══════════════════════════════════════════════════════════════════════════════

ORCHESTRATOR AGENT
│
├── Maintains loop state
├── Tracks iterations
├── Enforces minimum iterations (5)
├── Prevents premature exit
├── Accumulates soul discoveries
│
├── SUB-AGENT A: VISUAL COMPARATOR
│   │
│   ├── Takes screenshot of current state
│   ├── Places side-by-side with reference
│   ├── Performs squint test
│   ├── Reports FEELINGS not MEASUREMENTS:
│   │   ├── "Mine feels heavier"
│   │   ├── "Theirs feels more spacious"
│   │   ├── "Something about the top-right feels off"
│   │   └── NOT: "Border is 2px vs 4px"
│   │
│   └── Output: Perceptual observation document
│
├── SUB-AGENT B: DEEPENER
│   │
│   ├── Takes perceptual observation from Sub-Agent A
│   ├── Asks "What else?" three times
│   ├── Zooms into identified problem areas
│   ├── Asks forcing questions:
│   │   ├── "What am I seeing that I haven't named?"
│   │   ├── "If I trace this with my finger, where does it change?"
│   │   ├── "What's the quality of this space?"
│   │   └── "What would be lost if I removed this element?"
│   │
│   └── Output: Deepened observation with hypothesis
│
├── SUB-AGENT C: SINGLE-CHANGE IMPLEMENTER
│   │
│   ├── Takes hypothesis from Sub-Agent B
│   ├── Makes EXACTLY ONE change
│   ├── Documents what was changed and why
│   ├── Does NOT make additional "improvements"
│   │
│   └── Output: Modified component + change record
│
└── SUB-AGENT D: SOUL DOCUMENTER
    │
    ├── When a change works, captures WHY
    ├── Documents the PERCEPTUAL insight, not the CSS property:
    │   ├── "The container border was creating a 'trapped' feeling.
    │   │    Removing it let the content float in space.
    │   │    Sanrok content FLOATS, it's never CONTAINED."
    │   │
    │   └── NOT: "Removed border: 1px solid #ccc"
    │
    └── Output: Soul piece added to SOUL-DISCOVERIES.md

═══════════════════════════════════════════════════════════════════════════════
```

# PART 4: VISUAL AUDITING WITH PLAYWRIGHT

## Screenshot Comparison Protocol

```typescript
// perceptual-audit.spec.ts

import { test, expect } from '@playwright/test';
import * as fs from 'fs';

test.describe('Perceptual Deepening Audit', () => {

  const REFERENCE_PATH = 'reference-images/';
  const ATTEMPTS_PATH = 'audit-screenshots/';

    await page.goto('http://localhost:3000/component-under-audit');
    await page.waitForLoadState('networkidle');

  /**

   */
  test('capture-current-state', async ({ page }) => {

    Open both images. Squint. What FEELS different?

    DO NOT measure. DO NOT analyze CSS.
    Just look and feel.

   * STEP 2: Record squint test observation

  test('prompt-squint-observation', async () => {

    ════════════════════════════════════════════════════════════════════

  });

  /**
   * STEP 4: Zoom and observe
   */

    console.log(`
    ════════════════════════════════════════════════════════════════════
    ITERATION ${currentIteration} - ZOOM AND OBSERVE
    ════════════════════════════════════════════════════════════════════

    Look at it for at least 30 seconds.

    Ask yourself THREE times: "What else do I notice?"

    Answer in PERCEPTUAL-AUDIT-LOG.md:
    - "Looking closer, I notice: ___________"
    - "And also: ___________"
    - "And also: ___________"

    Each observation should be DIFFERENT.
    If you can't find three things, look harder.

    ════════════════════════════════════════════════════════════════════
    `);
  });

  /**
   * STEP 5: Name the problem
   */
  test('prompt-name-problem', async () => {
    console.log(`
    ════════════════════════════════════════════════════════════════════
    ITERATION ${currentIteration} - NAME IT
    ════════════════════════════════════════════════════════════════════

    Even if you're wrong, give a NAME to what you're seeing.

    Answer in PERCEPTUAL-AUDIT-LOG.md:
    - "I would call this: ___________"

    - "trapped text"
    - "weak borders"
    - "mushy letter endings"
```

# PART 5: SOUL DISCOVERIES DOCUMENT FORMAT

When perceptual insights are discovered through the deepening loop, they must be
documented in a specific way that captures the PERCEPTUAL truth, not just the
technical implementation.

Create and maintain: `SOUL-DISCOVERIES.md`

```markdown
# SOUL DISCOVERIES
## Perceptual Insights Extracted Through Deepening

═══════════════════════════════════════════════════════════════════════════════

This document contains the SOUL of the design system. Each entry represents
a perceptual truth that was discovered through iterative visual comparison,
not through analytical deduction.

These are not CSS rules. They are WAYS OF SEEING.

═══════════════════════════════════════════════════════════════════════════════

## SOUL PIECE #1: Content Floats, Never Trapped

**Discovered During:** Card system iteration 3
**Iteration Count:** 7 iterations to find this

**The Observation:**
"The reference card felt like the content was floating in space. Mine felt
like the content was in a box. I couldn't figure out why until iteration 5
when I realized: there's no visible container border in the reference. The
'card' is defined entirely by content grouping and whitespace, not by a
drawn boundary."

**The Perceptual Truth:**
Sanrok content FLOATS. It is never CONTAINED. When you add a border around
content, you create a prison. The content becomes trapped, defensive,
protected. Sanrok content is confident—it doesn't need protection. It claims
space by existing, not by being fenced in.

**The Technical Manifestation:**
- No container borders on cards
- Content grouping through proximity and whitespace
- If a border must exist, only ONE side (creates accent, not prison)

**How To Test:**
Remove all borders. Does the content still group logically? If yes, you
don't need the borders. If no, use whitespace, not borders.

---

## SOUL PIECE #2: Typography Creates Hierarchy, Not Containers

**Discovered During:** Essence Box iteration 4
**Iteration Count:** 6 iterations to find this

**The Observation:**
"I kept adding frames and borders to make the quote feel 'important.' But
the reference doesn't do that. The reference makes the quote important
through TYPOGRAPHY—larger size, italic, more whitespace around it. The
importance comes from the text itself dominating the space, not from a
decorative frame drawing attention to it."

**The Perceptual Truth:**
When you want something to feel important, don't FRAME it. ENLARGE it.
Let the typography itself create the hierarchy. Frames say "look at this
special thing inside the frame." Typography says "this IS the thing."

**The Technical Manifestation:**
- Important quotes: larger type, not bordered boxes
- Hierarchy through size differential (1.5x or more for important text)
- Whitespace as the "frame" rather than borders

**How To Test:**
Remove the frame/border. Is the content still clearly the focus? If not,
the typography isn't doing enough work. Increase size, increase whitespace.

---

## SOUL PIECE #3: Tension Through Opposition

**Discovered During:** Card header iteration 2
**Iteration Count:** 4 iterations to find this

**The Observation:**
"The reference has the title on the far left and the year on the far right.
They're in OPPOSITION—pulling against each other. Mine had them closer
together, which felt 'balanced' but also 'safe' and 'boring.' The opposition
creates energy."

**The Perceptual Truth:**
Sanrok compositions use TENSION, not balance. Elements are positioned in
opposition to each other, creating energy and interest. Safe, centered,
balanced layouts are generic. Opposition is editorial.

**The Technical Manifestation:**
- Title: flush left
- Year/metadata: flush right
- Maximum horizontal distance between key elements
- Space between is active, not dead

**How To Test:**
Push elements to opposite edges. Does it feel more energetic? If yes,
that's the Sanrok way.

---

## SOUL PIECE #4: Single-Edge Accents, Not Frames

**Discovered During:** Code block iteration 5
**Iteration Count:** 5 iterations to find this

**The Observation:**
"I kept trying full borders, then no borders, but neither felt right. The
reference uses a LEFT BORDER ONLY. It's not a frame (which contains), it's
an ACCENT (which indicates). The single edge says 'this is special' without
saying 'this is separate.'"

**The Perceptual Truth:**
When you need a visual marker, use ONE edge, not four. A frame separates
content from its context. A single-edge accent marks content while keeping
it connected to its context. Sanrok content is marked, not separated.

**The Technical Manifestation:**
- border-left only (4px red)
- NOT border on all sides
- The accent indicates, doesn't contain

**How To Test:**
If you have a border, reduce it to one edge. Does it still communicate
importance? If yes, the other edges were unnecessary containment.

---

## SOUL PIECE #5: Whitespace As Confidence

**Discovered During:** Component spacing iteration 8
**Iteration Count:** 8 iterations to find this

**The Observation:**
"I kept adding more content, more elements, more visual stuff. But the
reference has SPACE. So much space. At first it felt 'empty' to me. But
then I realized: the space IS the design. The space says 'we're so
confident in what we're showing, we don't need to fill every pixel.'"

**The Perceptual Truth:**
Whitespace is not absence. Whitespace is confidence. Generic designs fill
space because they're afraid of emptiness. Editorial designs embrace
emptiness because they trust their content. Cramped = desperate. Spacious
= confident.

**The Technical Manifestation:**
- Generous padding (2x what feels "comfortable")
- Don't fill space just because it's there
- Let content breathe

**How To Test:**
Double the whitespace. Does it feel more confident? If yes, the original
```

# PART 7: ANTI-PATTERNS TO AVOID

## What Breaks the Perceptual Deepening Loop

### ANTI-PATTERN 1: Analytical Escape
```
❌ WRONG: "Let me check the CSS properties..."
✓ RIGHT: "Let me look at what FEELS different..."

The moment you start measuring, you stop seeing.
Stay in perceptual mode until you've exhausted what you can see.
```

### ANTI-PATTERN 2: Premature Fixing
```
❌ WRONG: "I see three things wrong. Let me fix all of them."
✓ RIGHT: "I see three things wrong. Let me fix ONE, then re-look."

Fixing multiple things at once prevents learning.
You won't know which fix worked.
```

### ANTI-PATTERN 3: Checklist Regression
```
❌ WRONG: "Let me verify border-radius is 0, colors are correct..."
✓ RIGHT: "Let me squint and see if the overall feeling is right."

Checklists give false confidence.
Something can pass every check and still feel wrong.
```

### ANTI-PATTERN 4: Iteration Skipping
```
❌ WRONG: "It looks pretty close. 2 iterations is enough."
✓ RIGHT: "Minimum 5 iterations. What haven't I seen yet?"

The deepest insights come in iterations 4, 5, 6.
Early iterations catch obvious problems.
Later iterations catch soul problems.
```

### ANTI-PATTERN 5: Technical Documentation
```
❌ WRONG: Soul Discovery: "Changed padding from 16px to 24px"
✓ RIGHT: Soul Discovery: "Sanrok content breathes. Cramped = generic."

The CSS is not the insight.
The PERCEPTION is the insight.
```

### ANTI-PATTERN 6: "Nothing New" Surrender
```
❌ WRONG: "I don't see anything new this iteration."
✓ RIGHT: "I haven't looked hard enough. What am I avoiding?"

If you're not seeing new things, you're not looking.
Look at different scales (zoom in, zoom out).
Look at different areas.
Look at relationships, not just elements.
```
