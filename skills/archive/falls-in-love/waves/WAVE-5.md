# Wave 5: Combination Mastery

**Input:** CD-006 (re-read with deep integration focus), grammar.md, the HTML file as primary artifact.

**Minimum passes:** 8. **Expected passes:** 8-12. **Exhaustion signal:** Zero inline styles. All zone transitions typed. CSS architecture sound.

---

## The Critical Shift

This wave marks the transition from ADDITIVE to SUBTRACTIVE building. Waves 0-4 add new things. Wave 5 stops adding and starts understanding what already exists. If you are still inventing new components in Wave 5, you have not yet reached the maturity threshold. The signal of falling in love is when you stop wanting the page to be different and start wanting it to be more fully itself.

The subtractive shift is EVIDENCE of fusion. You stop adding because the content-form relationship feels complete -- not because you ran out of ideas. If you are still inventing new components at pass 5+, you have not crossed the threshold. The creative act now is not invention but clarification. Every removal sharpens the spatial argument. Every consolidation names what the page has become.

**Purpose:** How DD, OD, and AD mechanisms operate SIMULTANEOUSLY. Inline style elimination. Custom property consolidation. Transition grammar completion. Dead code removal.

---

## How to Read at Wave 5

Wave 5 has three inputs, and each is read through a fundamentally different lens than in previous waves. You are not reading for what to ADD. You are reading for how COMPOUND COMBINATION works -- and for where your page falls short of it.

### CD-006: Reading for Compound Operation

Re-read CD-006 with one question: "How do multiple dimensions operate simultaneously on the same elements?" CD-006 shows all dimensions active at once -- density, organization, and axis operating in compound on every element. Study the HOW, not the WHAT. You are not looking for techniques to import. You are looking for the PRINCIPLE of simultaneous operation -- what makes compound combination produce effects that no single dimension alone could.

The key observation: in CD-006, you cannot point to any element and say "that is the density element" or "that is the organization element." Every element carries all dimensions at different intensities. If you can still isolate dimensions on YOUR page -- "this zone is the density zone, that zone is the organization zone" -- your compound combination is not yet working.

### grammar.md: Reading as an Audit Tool

Do not read grammar.md as "what grammar rules should I apply?" Read it as "where does my page violate grammar rules I have been unconsciously following?" After 60+ passes, you have established patterns you treat as intentional. grammar.md gives you an external standard to audit those patterns against. Some of what you treat as intentional may be accidental. Some of what feels wrong may be a grammar rule you violated without knowing it. grammar.md is the mirror.

### Your Own HTML: Reading as Primary Artifact

Read your HTML top to bottom as if encountering it for the first time. The HTML is now a case study of your own building process. It carries the archaeology of 5 waves -- components added in wave order rather than architectural order, inline styles that survived because you stopped seeing them, dead code from approaches you abandoned, responsive blocks inserted before base styles, specificity conflicts accumulated through sustained building.

This is the most important reading of the wave. The HTML reveals architectural debts that are invisible when you build incrementally but obvious when you read the full source as a document.

## The Fundamental Cycle

Each pass is a full cycle: **Read reference --> build compound/subtractive CSS changes --> screenshot and scroll --> evaluate at system level --> refine --> decide what next.** Wave 5's cycle shifts from additive to subtractive -- but the cycle itself is the same. Even subtractive passes are full cycles. Removing dead code is not a task -- it is: identify dead code --> remove it --> screenshot --> evaluate whether the page's spatial argument is clearer without it --> refine --> decide what next. 8-12 passes means 8-12 full cycles.

### Why Subtraction Is a Creative Act

Inline style elimination is not cleanup. It is ARCHITECTURAL CLARITY. Inline styles obscure compound interactions -- when a property is set inline, it cannot participate in the cascade, cannot be overridden by media queries, cannot be seen in the context of its neighbors. Moving an inline style to a class is not a refactor. It is making the property VISIBLE to the system. Compound combination requires that every property participate in the cascade. Inline styles are compound combination blockers.

Dead code removal reveals the history of your building process and clarifies the page's spatial argument. Every dead selector is an abandoned hypothesis. Removing it is not cleanup -- it is acknowledging that the page has moved past that hypothesis. The CSS that remains after dead code removal is the CSS that ARGUES for the current spatial form.

Custom property consolidation is a form of NAMING. The names you give your properties express your understanding of the content. `--section-padding` is generic. `--institutional-compression` is semantic. The act of consolidating scattered values into named custom properties forces you to articulate what those values MEAN. If you cannot name a custom property, you do not yet understand what the value is doing.

## Identifying Compound Combination Opportunities

Where do DD + OD + AD already interact on the same elements? Where should they but do not?

The compound question: "If I removed one dimension entirely, would the others still work, or has the combination created irreducible wholes?" If removing density leaves the organization and axis work intact, the dimensions are applied in parallel, not in compound. True compound combination means the dimensions are entangled -- changing one changes the experience of all others on the same element.

Look for:
- Elements where density treatment and organizational treatment serve the SAME content argument (compound) vs elements where they serve different arguments (parallel -- not yet combined)
- Zone transitions where axis direction changes AND density shifts AND organizational structure transforms simultaneously (compound transition) vs transitions where only one dimension changes (sequential -- not yet combined)
- Responsive behavior where the compound effect adapts as a UNIT vs responsive behavior where each dimension has its own breakpoint logic (fragmented -- not yet combined)

The fusion test applies at the zone level: can you point to any single dimension and say "that carries this zone"? If YES, not yet compound. If the zone's quality is distributed across all dimensions with no single dimension carrying it, compound combination is working.

## Wave-Specific Staleness Signatures

Staleness at Wave 5 has characteristic forms that differ from staleness at earlier waves:

**Still inventing new components at pass 5+.** The builder has not reached the maturity threshold. The signal of Wave 5 readiness is wanting the page to be more fully ITSELF, not more DIFFERENT. If new components are still appearing, the builder is in additive mode -- still Wave 4 cognitively, regardless of process position.

**Treating subtractive work as "cleanup."** Removing dead code, eliminating inline styles, consolidating custom properties -- these are not janitorial tasks. They are creative acts that clarify the spatial argument. If the builder approaches subtraction with a "getting it tidy" mentality rather than a "making it clearer" mentality, the subtractive shift has not occurred.

**Never reading the full CSS top-to-bottom.** The builder works on individual components without reading the full architectural document. This misses architectural debts created by the wave process itself -- components added in wave order rather than logical order, specificity conflicts accumulated over 60+ passes, duplicate selectors from different waves addressing the same element.

**Evaluating component-by-component instead of system-level.** "Does this component work?" instead of "Does the SYSTEM of components create a coherent compound?" Component-level evaluation is Wave 2 thinking. Wave 5 evaluation is holistic -- the page as an interconnected system where changing one thing affects everything else.

**Inline styles surviving because "they are fine."** They obscure compound interaction. Every inline style is a property that cannot participate in the cascade, cannot respond to media queries, cannot be seen in architectural context. "Fine" is not the standard. Architectural clarity is the standard.

**Dead code left because "it does not hurt."** It clutters the architectural expression. Every dead selector is noise that makes the living architecture harder to read. Dead code does hurt -- it hurts comprehension of the system.

**Zero compound-combination observations in the notebook.** The builder writes about individual dimensions or individual components but never about how dimensions interact in compound on the same elements. The absence of compound observations means the builder is not yet seeing in compound -- still operating at the single-dimension level.

## Wave-Specific Retrospective Questions

At the end of Wave 5, the builder asks questions that could NOT be asked at any earlier wave -- questions about compound operation and architectural clarity:

1. **"When did I shift from wanting the page to be DIFFERENT to wanting it to be more fully ITSELF? Did that shift happen?"** This is the fundamental Wave 5 question. If the shift did not happen, the builder has not reached combination mastery. The answer should reference a specific moment -- a pass where the builder realized the page needed less, not more.

2. **"Where do DD + OD + AD operate simultaneously on the same elements? Can I name the compound effect?"** If the builder cannot name specific compound effects -- effects that emerge from dimensional interaction and that no single dimension produces alone -- compound combination is not yet working.

3. **"Is my CSS architecture EXPRESSIVE -- does the source order, naming, selector structure reflect the content's organization?"** The CSS is not just instructions for the browser. It is a document that expresses the builder's understanding of the content. If the CSS source order is arbitrary (wave order rather than content order), the architecture is not yet expressive.

4. **"What did reading the full CSS top-to-bottom reveal that I could not see while building incrementally?"** The answer should be specific -- duplicate selectors, specificity conflicts, inconsistent naming, dead code. If reading top-to-bottom reveals nothing, the builder either has unusually clean process or is not reading critically enough.

5. **"Am I evaluating at the system level or still component-by-component?"** The diagnostic: when the builder changes a property, do they check its compound effect on neighboring zones, or only its local effect? System-level evaluation means every change is assessed for ripple effects across the entire page.

## Cognitive Transformation Gate

The gate tests whether the builder has achieved compound combination mastery and architectural clarity.

### The Gate Conditions

1. **Has the builder shifted from additive to subtractive?** Are they making the page more ITSELF rather than more DIFFERENT? The evidence is in the notebook -- later passes should show removal, consolidation, and clarification rather than invention.

2. **Can the builder describe compound effects where multiple dimensions produce irreducible wholes?** Not "this zone has density AND organization" (parallel application) but "the density and organization on this element produce an effect that neither creates alone" (compound interaction). The builder should be able to name at least 3 such effects.

3. **Has the builder read the full CSS top-to-bottom and addressed architectural debts?** Duplicate selectors resolved. Source order reflects content logic. Specificity conflicts eliminated. The CSS is a readable document, not an archaeological record of the wave process.

4. **Zero inline styles remaining.** Not as a metric but as evidence of architectural clarity. Every property participates in the cascade. Every value is visible in its architectural context. Inline styles are compound combination blockers -- their absence means the architecture supports compound operation.

5. **All zone transitions typed in the transition grammar.** Every state change between zones is intentional and named. The behavioral dimension is complete. The reader's movement through the page is as designed as the page's static form.

### The Exhaustion Model

All three conditions must hold simultaneously:

- **Compound understanding complete:** The builder can describe how every zone operates in compound -- which dimensions interact, what the compound effect is, why it serves the content.
- **CSS architecture sound:** Zero inline styles. Zero dead code. Source order reflects content logic. Custom properties named semantically. The CSS is an expressive document.
- **Infinite time answer is invisible-grain compound refinement:** If the builder had unlimited additional time at Wave 5, they would be adjusting compound intensities at invisible-grain levels -- not restructuring, not adding, not subtracting. The architectural work is done. Only perceptual fine-tuning remains.

### What the Gate Is NOT

The minimum pass count (8) serves as anti-compression insurance ONLY. It is not the gate. A builder who reaches pass 8 and has not achieved compound combination mastery should continue. A builder who reaches pass 12 and meets all conditions should transition. The gate is cognitive transformation, not a counter.
