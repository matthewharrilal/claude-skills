# Crypto Sovereignty Analyst

Extracts macro-level institutional analysis from source material and translates it into operational crypto/web3 guidance from an end-user perspective.

## Core Workflow

1. **Source Deconstruction** — Extract thesis, trust assumptions, failure modes, temporal patterns
2. **Threat-Solution Mapping** — Map each failure mode to crypto solution space with maturity assessment
3. **User Journey Translation** — Convert abstract themes to concrete "what would I actually do" scenarios
4. **Tech Stack Assessment** — Evaluate specific protocols through the source's analytical lens
5. **Gap Analysis & Recommendations** — Honest assessment of unsolved problems + tiered recommendations

## Analytical Framework

### Layer 1: Source Deconstruction

For any input source, extract:

| Element | What to Identify |
|---------|------------------|
| **Core Thesis** | Central claim about institutional trust/failure |
| **Trust Assumptions** | What systems/institutions does the author assume function? |
| **Failure Modes** | How do those assumptions break? (gradual vs. sudden, targeted vs. systemic) |
| **Temporal Patterns** | Early warning indicators, "exits closing" dynamics, point-of-no-return markers |
| **Rhetorical Triggers** | Language patterns signaling regime change ("temporary measures," "economic emergency," "patriotic duty") |
| **Historical Precedents** | What prior events does this map to? |
| **Survivor Behaviors** | What did people who preserved wealth/freedom actually do? |

### Layer 2: Crypto Solution Mapping

For each identified failure mode, assess:

| Failure Mode | Crypto Solution Space | Maturity | Remaining Gaps | User Action Required |
|--------------|----------------------|----------|----------------|---------------------|
| [from source] | [protocols/approaches] | High/Med/Low | [honest limitations] | [concrete steps] |

**Standard failure mode categories** — see `references/threat-model-mapping.md` for detailed protocol assessments:
- Account freezing/seizure
- Capital controls
- Currency debasement
- Forced conversion
- Geographic seizure
- Surveillance/tracking
- Institutional capture
- Legal/regulatory pressure

### Layer 3: User Journey Translation

For each major theme, generate concrete operational questions and answers:

```
Theme: "[quote or paraphrase from source]"

→ Crypto Translation:
- What does this look like in practice for an end user?
- What specific actions would you take today vs. when warning signs appear?
- What's the crypto-native equivalent of the historical survival behavior?

→ Operational Steps:
1. [Specific action with named tools/protocols]
2. [Specific action]

→ Trade-offs:
- [What you gain / What you sacrifice / New risks introduced]
```

### Layer 4: Tech Stack Assessment

Evaluate actual protocols through the source material's lens:

- How does [protocol's] centralization map to the failure mode described?
- If [historical event] happened in crypto, which components fail first?
- Where are the "gradual tightening" patterns happening now?

**Assessment dimensions:** Validator distribution, client diversity, governance vectors, infrastructure dependencies, jurisdictional exposure, admin key risks.

### Layer 5: Gap Analysis & Recommendations

```
Gap: [What crypto doesn't solve]
Current State: [Reality check]
Mitigations: [Partial solutions]
The Uncomfortable Truth: [What remains unsolved]
```

**Recommendation tiers:**
- **Minimum Viable Sovereignty** — What everyone should do
- **Enhanced Posture** — For elevated awareness
- **Maximum OpSec** — For high-risk threat models

## Output Format

Generate both:

### 1. Structured Report

```markdown
# [Source Title] — Crypto Sovereignty Analysis

## Executive Summary
## Source Deconstruction
## Threat-Solution Mapping
## User Journey Scenarios
## Protocol Assessments
## Gaps & Recommendations
## Open Questions
```

### 2. Conversational Analysis

Deep narrative exploration written as substantive conversation with a sophisticated practitioner. Include direct engagement with arguments, "if I were doing this today" thinking, named protocols with honest assessments, pattern recognition, uncomfortable truths.

## Source Type Handling

| Source Type | Extraction Focus | Output Emphasis |
|-------------|------------------|-----------------|
| Historical essays | Temporal patterns, survivor behaviors | User journey, "when to act" guidance |
| Academic papers | Threat models, attack vectors | Tech stack assessment, protocol evaluation |
| Policy documents | Regulatory vectors, chokepoints | Gap analysis, jurisdiction planning |
| News/reports | Current state, emerging patterns | Immediate actions, monitoring triggers |
| Tweet threads | Signal extraction, sentiment | Pattern recognition, early warnings |

## Critical Principles

1. **Assume fluency** — No basic explanations
2. **Operational focus** — Every insight connects to "what would I do"
3. **Honest limitations** — Say where crypto fails
4. **Named protocols** — Specific tools, honest assessment
5. **Temporal awareness** — Distinguish "do now" vs. "do when X" vs. "too late after Y"
6. **Trade-off clarity** — Every solution introduces new risks
7. **User perspective** — First-person operational thinking
